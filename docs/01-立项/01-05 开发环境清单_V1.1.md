## 一、文档说明

### （一）编写目的

本文规定团队开发环境的软件版本、安装路径示例、配置方式和检查标准。六份立项文档定稿后，全组依据本方案开展环境安装、最小示例部署及运行验证。具体有三个目标：

> **1. 统一**：五名成员使用约定的软件版本、相同的项目目录结构和配置模板；个人安装路径可不同，减少“只有我这儿能跑”的争论。
>
> **2. 可验**：每条基线都对应一条检查命令和预期输出，不靠感觉判断。
>
> **3. 可复现**：依据本文配置模板和第七章验收步骤，在 1 小时内完成最小 SSM 示例的部署与验证；答辩换机器也能快速恢复。

### （二）适用范围

> • 适用于本项目全体成员：项目负责人、需求负责人、开发负责人、前端负责人、测试与文档负责人。
>
> • 适用于开发机、联调机与答辩演示机；同一台机器上多人轮换开发时，也按本文档检查。
>
> • 不适用于生产服务器。生产部署另见 06-01《部署手册》，数据库、Redis 与 Tomcat 的安全配置以部署手册为准。
>
> • 本文主方案以 **Windows 10/11 x64** 为基线；macOS 成员按附录 D 配置，本机运行 JDK、Maven、Tomcat 与 IDEA，数据库和缓存采用容器方案。Linux 成员参照相同服务版本配置，并记录实施方式。

### （三）环境管理原则


| 类别 | 包含内容 | 管理要求 |
| --- | --- | --- |
| 统一基线<br> （按约定版本核对） | JDK 17、Maven 3.9.9、Tomcat 10.1.61、MySQL 5.7.17、Redis 5.0.14.1、pom.xml 依赖版本、数据库字符集与时区 | 依赖及服务版本以本文档和 pom.xml 为准，不得自行升级；JDK 统一为 17，补丁版本按第二章登记。 |
| 弱一致<br> （版本可不同） | IntelliJ IDEA 2025.2+、Git 2.x、Chrome/Edge 131+、数据库客户端、Postman/Apifox | 不进入构建产物，但需在环境配置记录中记录；出现问题时能说清版本。 |

把“强一致”和“弱一致”分开，是为了避免两种极端：一种是什么都要求一模一样，连 IDE 版本都强制，浪费时间；另一种是什么都不统一，最后联调靠猜。统一依赖、构建工具及关键运行配置；JDK 补丁版本和个人工具按本章约定登记。安装目录与仓库所在目录由各成员自行选择，不作为版本一致性的判据。

## 二、环境基线

环境基线由「机器 → 操作系统 → 运行时 → 构建工具 → 中间件 → 项目依赖」六层组成。任何一层漂移，都可能在联调时放大成难查的问题。本章先给出一张总表，后续章节再逐项展开安装与配置。

### （一）硬件与操作系统

| --- | --- | --- |

### （三）版本兼容性说明

下面六组关系是本项目最容易踩坑的地方，版本不能只看“新不新”，要看“配不配”。

> • **Spring 6.2.11 + JDK 17 + Tomcat 10.1.61**：Spring 6.2 要求 Java 17+，Tomcat 10.1 实现 Servlet 6.0，包名统一 jakarta.\*。这是必须整组锁定的一组。
>
> • **MySQL 5.7.17 + Connector/J 8.0.33**：可用；本项目显式设置 serverTimezone=Asia/Shanghai，以统一时区配置。不要用 MySQL 8.0 的 caching_sha2_password 默认认证，5.7 不支持。
>
> • **Redis 5.0.14.1 + Jedis 4.4.8**：可用；Jedis 3.x 与 4.x 的 API 有差异，禁止个人随意升级。
>
> • **JSP + JSTL 3.0**：使用适配 Jakarta 的 JSTL 3.0 API 和实现，不引入基于 javax 的旧 JSTL 1.2 实现。项目统一推荐 jakarta.tags.core；Tags 3.0 仍允许旧 java.sun.com 标签 URI，不能仅凭 URI 判断依赖是否兼容。
>
> • **iText 5.5.13 + itext-asian 5.2.0**：采用 STSong-Light 等 CJK 字体方案时需配套 itext-asian；也可使用包含中文字形的字体文件并嵌入 PDF。中文显示取决于字体、编码和嵌入方式，应在不同阅读器中验证，不能只检查依赖是否存在。
>
> • **Druid 1.2.23**：仅使用 DruidDataSource；不要启用基于 javax.servlet 的监控 Servlet，需要监控时用 MySQL/Redis 自带工具。

### （四）版本锁定策略

> • pom.xml 中用 <properties> 集中管理版本，不写 LATEST、RELEASE，也不依赖“碰巧解析到”的传递版本。
>
> • 任何依赖升级必须走第八章的变更流程，附 mvn dependency:tree 前后对比，确认没有把 javax.servlet 带回来。
>
> • 提交前执行 mvn -q clean package，确保依赖可解析、编译通过、WAR 能生成；不在 IDEA 里手动往 WEB-INF/lib 拷 jar。
>
> • 数据库脚本、Redis key 命名、时间格式也属于“环境”的一部分，按第六章约定执行，避免同一份代码在不同机器上出现不同结果。

## 四、环境变量

环境变量是把“安装目录”告诉命令行、Maven、Tomcat 与 IDEA 的桥梁。配置错了，最常见的表现是：java 能运行，但版本不对；mvn 能用，但用的是 IDEA 捆绑的 Maven；Tomcat 启动一闪而过。

### （一）变量清单

| **变量** | **值** | **作用** |
| --- | --- | --- |
| **JAVA_HOME** | D:\develop\jdk-17 | Maven、Tomcat、IDEA 定位 JDK。 |
| **MAVEN_HOME** | D:\develop\apache-maven-3.9.9 | Maven 安装目录。 |
| **CATALINA_HOME** | D:\develop\apache-tomcat-10.1.61 | Tomcat 安装目录。 |
| **Path（追加）** | %JAVA_HOME%\bin;%MAVEN_HOME%\bin;%CATALINA_HOME%\bin | 命令行可直接使用 java、mvn、catalina。 |
| **MAVEN_OPTS** | -Xmx1024m -Dfile.encoding=UTF-8 | 防止 Maven 中文乱码与内存不足。 |

### （二）设置步骤

> **1.** 按 Win + R，输入 sysdm.cpl，打开“系统属性 → 高级 → 环境变量”。
>
> **2.** 在“用户变量”中新建 JAVA_HOME、MAVEN_HOME、CATALINA_HOME，值分别为上表中的路径。
>
> **3.** 编辑 Path，把 %JAVA_HOME%\bin、%MAVEN_HOME%\bin、%CATALINA_HOME%\bin 追加到最前面。
>
> **4.** 新建 MAVEN_OPTS，值为 -Xmx1024m -Dfile.encoding=UTF-8。
>
> **5.** 关闭所有终端与 IDEA，重新打开，使变量生效；只开新终端、不关 IDEA，IDEA 仍可能读旧值。

**CMD 方式（可选；先将示例路径替换为本机实际路径）**


```text
setx JAVA_HOME "D:\develop\jdk-17"
setx MAVEN_HOME "D:\develop\apache-maven-3.9.9"
setx CATALINA_HOME "D:\develop\apache-tomcat-10.1.61"
setx MAVEN_OPTS "-Xmx1024m -Dfile.encoding=UTF-8"
```


| **注意：**不要用 setx Path 直接追加路径：setx 会把超过 1024 字符的 Path 截断，导致其他软件命令丢失。Path 请用图形界面修改，或用 \[Environment\]::SetEnvironmentVariable 读取后拼接再写回。 |

## 五、软件安装与配置

本章按“运行时 → 构建工具 → 容器 → 数据库 → 缓存 → 版本管理 → IDE”的顺序展开。每个小节都给出基线、安装步骤、关键配置与验证命令；配置模板直接收录于本章、第六章及附录 B，按附录 C 的位置复制到本机使用。

### （一）JDK 17

**基线**：Eclipse Temurin 17.0.13+11（LTS），安装到 D:\develop\jdk-17。

选择 Temurin 而不是 Oracle JDK，是因为它免费、跨平台、更新路径清晰，团队成员踩坑少。Oracle JDK 17 也能跑，但本团队不混用，避免出现“有人用 Oracle、有人用 Temurin”的补丁差异。

> **1.** 从 Adoptium 官网下载 Temurin 17 → Windows x64 → JDK → .zip（或 .msi）。
>
> **2.** 解压或安装到 D:\develop\jdk-17，确认 bin\java.exe、bin\javac.exe 存在。
>
> **3.** 按第四章设置 JAVA_HOME，并把 %JAVA_HOME%\bin 放到 Path 最前。
>
> **4.** 打开新终端，执行 java -version 与 javac -version，两者大版本均应为 17，并使用同一套 JDK；其他 17.0.x 补丁按环境配置记录记录。
>
> **5.** IDEA：File → Project Structure → SDKs → Add JDK，选择 D:\develop\jdk-17；Project 的 Language level 设为 17。

**验证输出**


```text
java -version
# openjdk version "17.0.13" 2024-10-15
# OpenJDK Runtime Environment Temurin-17.0.13+11 (build 17.0.13+11)
javac -version
# javac 17.0.13
```


| **注意：**项目统一用 JDK 17，不要用机器上已有的 JDK 25 直接跑。JDK 25 可以并存，但 JAVA_HOME、IDEA SDK、Tomcat JRE 三处都必须指向 17；若编译产物要求的 Java 版本高于 Tomcat 实际使用的 Java 版本，可能发生字节码版本不兼容；应同时核对编译目标和运行时。 |
| --- |

### （二）Maven 3.9.9

**基线**：Apache Maven 3.9.9，安装到 D:\develop\apache-maven-3.9.9。

> **1.** 下载 apache-maven-3.9.9-bin.zip，解压到目标路径，不要运行安装程序。
>
> **2.** 参考附录 B，在个人用户目录 .m2/settings.xml 中配置镜像及可选本地仓库路径；已有配置先核对合并，不直接覆盖。共享模板以附录 B 为准。
>
> **3.** 确认 localRepository 指向本机有效目录（或使用默认目录），镜像为阿里云。
>
> **4.** 执行 mvn -v，确认 Maven 3.9.9 且运行在 Java 17 上。
>
> **5.** 执行 mvn help:effective-settings，确认本地仓库与镜像已生效。

**settings.xml 关键片段**


```xml
<localRepository>D:/develop/m2-repository</localRepository>
<mirror>
  <id>aliyun</id>
  <mirrorOf>central</mirrorOf>
  <url>https://maven.aliyun.com/repository/public</url>
</mirror>
```


| **注意：**不要用 IDEA 捆绑的 Maven，也不要在命令行临时加 -Dmaven.compiler.source=17 代替 pom 配置。团队以 pom.xml 的 <maven.compiler.release>17</maven.compiler.release> 为准，保证所有机器编译出的字节码一致。 |
| --- |

### （三）Tomcat 10.1.61

**基线**：Apache Tomcat 10.1.61，安装到 D:\develop\apache-tomcat-10.1.61。

### （五）数据库与缓存初始化约定

> • schema.sql 使用 CREATE TABLE IF NOT EXISTS 避免重复建表报错，但不会自动更新已有表结构；结构变更另写增量脚本。data.sql 仅放演示数据，使用 INSERT ... ON DUPLICATE KEY UPDATE 前须明确覆盖字段，不对真实业务数据重复导入；升级脚本按 V20261107\_\_init.sql 命名。
>
> • 表名统一小写，引擎 InnoDB，字符集 utf8mb4；时间字段用 DATETIME，默认 CURRENT_TIMESTAMP；金额用 DECIMAL(10,2)。
>
> • Redis key 统一前缀 campus:，例如 campus:tag:user:1001、campus:hot:1；标签缓存 TTL 30 天，过期后根据业务数据重建；TTL 仅控制缓存有效期，不承担推荐权重计算；禁止 keys \* 遍历。
>
> • 初始化顺序：schema.sql → data.sql → 应用启动；重复导入前先备份，避免把测试数据覆盖到联调库。
