## 一、计划说明

### （一）编制目的

通过统一的阶段安排和任务跟踪方式，使团队明确项目在 8 周内需要完成的工作、阶段成果、责任角色及评审节点，降低任务遗漏、进度冲突和后期集中返工的风险。

- 明确项目从立项准备、需求分析、系统设计到编码、测试和交付的整体推进顺序。
- 将各阶段工作拆分为可检查的任务，并明确主要责任角色和前后依赖。
- 以 M1—M5 作为阶段检查点，及时发现需求、设计、开发和测试中的偏差。

### （二）计划依据

- 《01-01 项目立项书》：项目目标、建设范围、团队角色与模块、8 周 / 60 课时进度安排、里程碑及风险预案。
- 《01-05 开发环境清单》：开发环境统一要求，作为立项准备阶段和编码阶段的环境前置条件。
- 课程实践项目安排及五名成员当前确认的角色分工。

### （三）计划范围与假设

- 本计划覆盖项目全周期的阶段任务与交付安排，不替代需求规格说明书、系统设计文档、测试用例或部署手册。
- 本期按课程项目交付，使用模拟账号与脱敏数据验收，真实用户试用留待后续。项目以立项书列出的 4 大类、15 个功能模块为完整目标，裁剪时同步调整验收范围；具体功能点与优先级在第 2—3 周需求分析阶段细化。
- 计划周期为 2026-11-09—2027-01-03，共连续 8 周，阶段课时合计 60 课时；阶段存在交叉，例如需求分析与系统设计、系统设计与编码准备可按立项书安排衔接。
- 计划投入 300 人·课时，额外缓冲 35 人·课时，预计总投入 335 人·课时。缓冲集中安排在第 6 周末至第 7 周初，按需用于延期、缺陷修复和联调，不安排常规新功能，实际投入另行登记。

## 二、项目概况与组织

| 项目项 | 计划内容 |
| --- | --- |
| 项目名称 | 校园闲置互助流转平台（Campus Loop） |
| 项目目标 | 建设面向校内学生、公益社团及管理员的闲置互助流转 Web 平台，支持以物易物、低价寄售、技能交换和闲置快捐等场景。 |
| 项目周期 | 2026-11-09—2027-01-03（连续 8 周 / 60 课时） |
| 技术路线 | Java SSM：Spring 6.2.11 + SpringMVC + MyBatis 3.5.19；MySQL 5.7、Redis 5.0；JSP + Bootstrap 5 + ECharts；JDK 17、Tomcat 10.1.61。 |
| 项目边界 | 不介入线上资金交易，不提供物流配送，不直连学校真实内网生产库；以校内身份核验和线下面交为主。 |
| 主要交付 | 可运行 Web 系统、数据库脚本、测试材料、部署与用户文档、项目总结及答辩材料。 |

## 七、任务依赖与协作机制

### （一）关键任务依赖

1. 需求分析依赖立项阶段明确的项目目标、用户范围和建设边界；需求结论是系统设计的输入。
2. 系统设计依赖需求基线；数据库结构、接口定义和页面交互应在 M3 评审后冻结，避免编码阶段反复变更。
3. 编码实现依赖开发环境可用、工程骨架和设计成果；跨模块调用应先确认接口约定再并行开发。
4. 系统测试依赖可运行的集成版本、需求验收标准和测试用例；缺陷由对应模块负责人修复，测试负责人组织回归。
5. 交付与答辩依赖测试评审通过、部署流程可复现以及文档和演示材料齐备。

### （二）沟通与进度跟踪

- 每周至少进行两次简短进度核对，检查已完成事项、下一步计划、阻塞问题和需要协助的任务。
- 各成员按统一的任务记录方式更新任务状态；建议状态为：未开始、进行中、待协助、待验收、已完成。
- 代码与文档统一使用 Git 进行版本管理；重要阶段成果应提交并保留版本记录。
- 跨模块接口、数据结构或需求口径发生变化时，先在团队内确认，再同步更新相关设计与任务记录。

### （三）变更管理

- M2 需求评审和 M3 设计评审后，原则上冻结本期 15 个模块范围及关键设计。
- 新增需求或范围调整先登记变更原因、影响模块、预计工作量和进度影响，由项目负责人组织评估。
- 不影响本期核心目标但会增加工作量的新增想法，优先纳入二期迭代计划；经团队确认后方可调整本期计划。

### （一）功能裁剪预案

若到第 6 周末主流程仍未调通，依据立项书 Plan B，经项目负责人（蒋岳霖）组织确认并登记变更后，立即启动功能裁剪预案，优先暂缓“11. 统计分析与数据看板”和“15. 换物集市与主题活动”两个非核心外围模块（原估算共 24 人·课时，实际可重分配量按未完成工作核算），全组集中精力保障“物品发布 → 双模式流转 → 预约扫码核销 → 闲置快捐凭证 → 诚信积分”核心主链路 100% 完整可用，并同步记录对验收范围的影响。

### （二）答辩故障预案

第 8 周答辩前，除校园网测试环境外，至少在 2 名组员的笔记本电脑上准备可离线运行的本地环境，并提前录制一份完整系统演示视频，以降低现场网络或服务器故障对答辩的影响。

## 十、计划执行与更新
