# 一、概述

## （一）编写目的

本文档在《01-01 项目立项书（V1.1）》定稿与课程需求确认后编写，用于明确系统的总体架构、15 个业务模块边界、页面结构与交互要点、50 个对外接口契约、15 张数据表结构及变更影响范围，供开发拆解任务、测试编写用例以及评审检查方案完整性。

按“唯一真源”原则，本文档只定义“有哪些模块、对外契约与数据结构是什么”，不写类图、方法签名、伪代码与建表 SQL 代码块；类与方法级实现由《需求详细设计文档（DDD）》承担，视觉规范与页面成品由《UI 设计稿》承担。

# 二、总体设计

## （一）设计目标与约束

系统面向校内闲置互助场景，注册用户规模在千级、日活百级，属于轻量级校园 Web 应用。设计目标按优先级排列如下：

1、正确性优先：双模式锁单、成对解锁、核销完成、积分增减与捐赠入库涉及物品归属和信用记录，优先保证状态与数据准确。

2、结构简洁易维护：遵循标准 SSM 五层结构，模块划分与 5 人分工一致，成员间可通过接口和表结构独立并行开发。

3、必要扩展与降级：双模式流转、积分规则和站内通知通过统一状态与配置表收口；Redis、PDF 生成等非核心依赖异常时可平滑降级，不阻断主流程。

约束条件：

1、框架与容器固定为 Spring 6.2.11 + SpringMVC + MyBatis 3.5.19、JDK 17、Tomcat 10.1.61、MySQL 5.7.17、Redis 5.0，不引入 Spring Boot，采用 JSP + Bootstrap 5 + ECharts 服务端渲染。

2、项目边界遵循《01-01 项目立项书》：不接入线上资金支付、不提供物流配送、不直连学校真实内网生产库；保留“学号 + 校园邮箱核验”的认证定位与扩展预留，课程演示采用预置模拟账号。

3、统一技术契约：密码采用 BCrypt 不可逆哈希存储；所有主键与业务 ID 统一使用 MySQL `INT` / Java `Integer`；所有金额统一使用 `decimal(10,2)` / `BigDecimal`，禁用 `float`/`double`。

## （二）系统架构

请求沿“表现层 → 控制层 → 业务层 → 数据访问层 → 存储层”自上而下流转，数据查询与更新全部收口在 Mapper 层：

| 层次 | 职责 | 技术与约束 |
| --- | --- | --- |
| 表现层 | 页面渲染、表单校验、异步交互与图表展示 | JSP + Bootstrap 5 + Ajax + ECharts；统一顶部导航、每页 12 条分页、写操作二次确认 |
| 控制层 | 参数格式校验、角色判定与结果封装 | SpringMVC `@Controller`/`@RestController`，数据接口统一返回 `Result<T>` |
| 业务层 | 业务规则、状态机流转、并发控制与事务边界 | Spring `@Service`，跨表写操作与成对锁/解锁统一使用 `@Transactional` |
| 数据访问层 | SQL 映射与组合分页查询 | MyBatis Mapper 接口 + XML，参数一律使用 `#{}` 占位，禁止 Service 拼 SQL |
| 存储层 | 业务数据持久化、轻量缓存与文件存储 | MySQL 5.7（库 `campus_loop`）、Redis 5.0、应用外部本地目录（`upload/`、`certificate/`） |

横切逻辑通过拦截器、AOP 切面与全局异常处理器独立挂载：登录与权限拦截器负责会话与角色放行；`@OperLog` 切面负责异步审计留痕；`@ControllerAdvice` 统一将参数、业务及系统异常转换为标准错误码响应。

## （四）运行环境与部署拓扑

采用单机轻量部署：单台主机运行 Tomcat 10.1.61 承载应用 WAR 包，同机或内网独立主机部署 MySQL 5.7.17 与 Redis 5.0；用户上传图片（`upload/`）与电子捐赠凭证（`certificate/`）存放在 Tomcat 应用目录之外，通过静态路径映射提供只读访问，避免重新发包丢失文件。

# 三、模块设计（含界面设计）

本章按立项书 01～15 顺序逐个描述各模块的职责、功能要点与界面设计。界面表中的页面名直接对齐《需求设计交付任务书》20 页 UI 清单（以 `[UI-01]`～`[UI-20]` 标明对应关系），供《UI 设计稿》绘制与前端还原使用。

全站共用以下交互约定：顶部统一 5 入口导航与信用分、消息红点、头像菜单；列表页默认每页 12 条并支持状态筛选；写操作均含前端校验、二次确认与结果提示；状态标签遵循 6 类语义色（循环绿 `#0F8A6A`、寄售蓝 `#3B82F6`、公益紫 `#7C3AED`、琥珀 `#F59E0B`、危险红 `#EF4444`、正文墨 `#111827`）；空列表、加载中、失败重试与无权限态均给出明确提示。

## （一）用户登录与权限控制（模块 01）

模块职责：提供学生、公益社团、管理员三角色统一登录、会话维持、权限拦截与安全退出。

功能要点：1）登录校验账号存在性、账号状态（`user.status`：`1` 正常、`0` 停用，停用返回 `1005`）与 BCrypt 密码哈希（失败统一返回 `1004`），通过后在 Session 写入 `userId`、`username`、`role`、`campus`、`authStatus` 并按角色跳转；2）校园认证状态 `user.auth_status` 取值 `0` 未认证（仅浏览，写操作返回 `1003`）、`1` 已认证、`2` 驳回，保留邮箱核验模型，演示期使用预置已认证账号；3）拦截器对未登录接口返回 `1002`，越权访问返回 `1003`；4）退出登录销毁服务端 Session。

### 1、界面设计

| 页面 | 主要区域与控件 | 关键交互 |
| --- | --- | --- |
| 登录页 `[UI-01]` | 角色切换标签、账号与密码输入框、登录按钮、演示账号说明 | 前端非空校验、支持回车提交；失败提示“账号或密码错误”；成功后按角色跳转对应首页 |
| 全站导航与退出入口 | 顶部导航菜单、信用分徽章、未读铃铛、头像下拉（个人中心/改密/退出） | 学生端不显示后台与社团入口；点击退出需二次确认并返回 `[UI-01]` |

## （二）闲置物品发布与管理（模块 02）

模块职责：负责闲置物品的多图发布、合规校验、编辑、上下架、逻辑删除与详情展示。

功能要点：1）支持上传 1～5 张实物图（单张 ≤ 2MB，JPG/PNG/WebP，超限返回 `2001`），压缩存储并默认首图为封面；2）发布校验标题（4～40 字）与描述敏感词、寄售价格 > 0 且 ≤ 同类均价 3 倍（异常返回 `2002`）、在售上限 10 件（超限返回 `2003`）及信用分门槛（受限返回 `2004`）；3）状态机 `item.status`：`0` 待审核 → `1` 在售 → `2` 锁定 → `3` 已完成，`0`/`1` 可下架为 `4` 已下架，`4` 重提回 `0`，非法流转或编辑/删除锁定物品返回 `2102`；4）删除统一逻辑删除（`is_deleted=1`），确保历史单据可追溯。

### 1、界面设计

| 页面 | 主要区域与控件 | 关键交互 |
| --- | --- | --- |
| 物品详情 `[UI-04]` | 多图轮播、标题/成色/校区/价格或期望物品、卖家信用、下单/快捐/收藏/举报按钮 | 未登录可浏览，交互前提示登录；非在售态灰显隐藏交易按钮；本人物品切换为管理入口 |

| 我的闲置 `[UI-06]` | 状态筛选 Tab、物品卡片列表、编辑/下架/删除按钮、分页条 | 下架与删除需二次确认；锁定态禁用编辑和删除；空态引导跳转 `[UI-05]` |

## （三）双模式流转（模块 03）

模块职责：用统一流转单承载以物易物与低价寄售，处理并发防重锁单与异常成对解锁。

功能要点：1）以物易物须指定发起人 1 件在售物品作为 `offer_item_id`，事务内用条件更新同时锁定目标与换出物品，任一影响行数为 0 即回滚并返回 `2101`；低价寄售仅锁目标物品，线下当面结清款项；2）状态机 `exchange_order.order_status`：`0` 待确认 → `1` 已确认 → `2` 待面交 → `3` 已完成，异常分支 `4` 已取消（须填原因）、`5` 已违约（超时关闭），越级或向自己下单返回 `2102`；3）取消、超时与违约三条路径均在同一事务内成对解锁双方物品回 `1` 在售。

### 1、界面设计

| 页面 | 主要区域与控件 | 关键交互 |
| --- | --- | --- |
| 发起交换 `[UI-07]` | 目标物品摘要、模式徽章、我的可换物品单选区（交换模式）、留言框、提交按钮 | 交换模式未选换出物品时按钮禁用；提交前二次确认锁定提示；被抢先时引导返回列表 |
| 流转单详情 `[UI-08]` | 状态步骤条、双方物品与信息卡、预约摘要、动态操作按钮（确认/取消/预约/评价） | 按状态和当前身份渲染可执行操作；取消需填原因并二次确认；待面交态直达 `[UI-09]` |

## （四）技能交换板块（模块 04）

模块职责：支持学生发布技能提供与技能需求，按标签检索、识别互补关系并发起互换邀约。

功能要点：1）分“我能提供（`1`）”与“我需要（`2`）”两类，单账号同类有效记录最多 3 条（超限返回 `2201`）；2）状态 `skill.status` 取值 `1` 有效、`0` 已关闭，对已关闭技能邀约返回 `2102`；3）支持按名称、类型、熟练度检索，详情页比对当前用户与发布者双向标签并标注“高度互补”；4）不可邀约本人（返回 `2202`），邀约写入站内通知，完成互换按规则加分。

### 1、界面设计

| 页面 | 主要区域与控件 | 关键交互 |
| --- | --- | --- |
| 技能大厅 `[UI-10]` | 关键词/类型/熟练度筛选条、技能卡片网格、发布技能入口、分页条 | 筛选回显条件；互补卡片带绿色角标；同类满 3 条禁用发布；空态提供发布引导 |
| 技能详情 `[UI-11]` | 技能信息、服务说明、“高度互补”标识、发布人信用、互换邀约弹窗 | 本人技能显示编辑/关闭；提交邀约二次确认后提示已发站内通知 |

# 四、接口设计

## （一）接口规范

| 规范项 | 约定 |
| --- | --- |
| 风格与路径 | RESTful 资源复数风格，统一前缀 `/api`，资源名全小写 |
| 方法约定 | 查询用 `GET`，新增、状态变更与逻辑删除统一用 `POST`（便于表单兼容与审计） |
| 数据格式 | `GET` 用 Query String；写接口用 `application/json`（UTF-8），上传文件用 `multipart/form-data` |
| 统一响应 | HTTP 状态码固定 `200`，响应体为 `Result<T>{code, msg, data}`，靠 `code` 区分结果 |
| 分页协议 | 入参 `page`（默认 1）、`pageSize`（默认 12，最大 50）；出参 `PageInfo<T>{total, list, pages}` |
| 鉴权与类型 | 基于 HttpSession 鉴权；业务 ID 统一 `Integer`，金额 `BigDecimal`，时间 `yyyy-MM-dd HH:mm:ss` |
| 幂等兜底 | 写接口依托数据库唯一索引与状态条件更新保证幂等，不依赖前端去重 |

## （二）统一响应与错误码

成功返回 `code=0`、`msg="ok"`；失败按 4 位业务域分段编码（`10xx` 认证鉴权、`20xx` 物品、`21xx` 流转核销、`22xx` 技能捐赠、`23xx` 信用密码、`24xx` 活动、`50xx` 系统与依赖），便于 5 人并行开发且避免号段冲突。

| 错误码 | 含义 | 触发场景 |
| --- | --- | --- |
| 0 | 成功 | 正常完成 |
| 1001 | 参数错误 | 必填缺失、格式非法、驳回理由为空 |
| 1002 | 未登录 | Session 缺失或已过期 |
| 1003 | 无权限 / 越权 | 角色不符、非资源归属方、非本社团数据、未认证发布 |
| 1004 | 账号或密码错误 | 登录账号不存在或 BCrypt 校验失败 |
| 1005 | 账号已停用 | `user.status = 0` |
| 2001 | 图片不合规 | 数量不在 1～5 张、单张 > 2MB 或格式非白名单 |
| 2002 | 价格不合法 | 寄售价格 ≤ 0 或超过同类均价 3 倍 |
| 2003 | 发布数量超限 | 同时在售物品达 10 件 |
| 2004 | 信用分受限 | 低于 40 分观察期或低于 60 分受限在售数 |
| 2101 | 物品已被抢先 | 并发锁单条件更新影响行数为 0 |
| 2102 | 状态不允许 | 越级流转、重复审核、操作锁定物品、向本人下单 |
| 2103 | 核销码无效 | 核销码不存在、不匹配或已使用 |
| 2104 | 订单已超时关闭 | 超过预约时间 24 小时已被关闭 |
| 2201 | 技能数量超限 | 同类有效技能超过 3 条 |
| 2202 | 不可邀约本人 | 发起人为技能所有者 |
| 2203 | 物品不可捐赠 | 非本人所有或非在售状态 |
| 2301 | 重复评价 | 触发评价唯一索引 `uk_order_from` |
| 2302 | 超过评价期限 | 订单完成超过 7 天 |
| 2303 | 原密码错误 | 改密时旧密码校验失败 |
| 2401 | 活动名额已满 | Redis Lua 或行锁扣减剩余名额为 0 |
| 2402 | 重复报名 | 触发活动报名唯一索引 `uk_activity_user` |
| 5001 | 系统异常 | 未捕获异常统一兜底 |
| 5002 | 依赖不可用 | Redis 连接异常或 PDF 生成失败 |

# 五、数据库设计

## （一）设计原则

1、库名固定为 `campus_loop`，字符集 `utf8mb4`，引擎 `InnoDB`；表名与字段名统一小写下划线，实体类属性采用驼峰并在 MyBatis XML 显式映射。

2、主键统一自增 `int`（与 Java `Integer` 对应）；金额统一 `decimal(10,2)`；时间统一 `datetime` 并由数据库默认值维护；状态统一 `tinyint` 且在注释列全取值。

3、历史业务主表（`item`、`activity`）采用逻辑删除 `is_deleted`；普通索引以 `idx_` 命名，唯一索引以 `uk_` 命名。

## （三）表间关系

`user` 是全局主表，其余业务单据与审计表均通过各自的用户 ID 字段关联至 `user.id`。`item` 与 `item_image` 为一对多关系，并通过 `category_id` 关联 `category`。`exchange_order` 同时关联物品（`item_id`、`offer_item_id`）与双方用户（`from_user_id`、`to_user_id`）；`donation` 关联物品、捐赠人与社团三方；`credit_log` 与 `review` 分别经 `ref_id`、`order_id` 回溯至具体业务单据；`activity_join` 关联 `activity` 与 `user`。

## （五）Redis 键设计

全部键统一加 `cl:`（Campus Loop）业务前缀隔离，均带过期时间：

| 键模板 | 结构 | 用途 | 过期时间 |
| --- | --- | --- | --- |
| `cl:tag:user:{userId}` | ZSet | 用户标签权重（浏览 +1、收藏 +3、发布 +5） | 30 天 |
| `cl:rank:hot:{campus}` | ZSet | 校区在售热门物品榜，冷启动兜底 | 1 天 |
| `cl:rec:cache:{userId}` | String (JSON) | 首页个性化推荐 12 条结果缓存 | 10 分钟 |
| `cl:search:hot` | ZSet | 全校热门检索词榜 | 7 天 |
| `cl:act:quota:{activityId}` | String (Int) | 活动剩余名额，配合 Lua 原子扣减 | 活动结束后 24 小时 |
| `cl:auth:code:{studentNo}` | String | 校园邮箱身份核验验证码（预留扩展） | 5 分钟 |

# 六、非功能性设计

## （一）性能

在 10 万条模拟物品数据下，首页与多条件检索接口响应 ≤ 300ms，其余业务接口 ≤ 500ms，支持 50 并发稳定访问。通过按需取列、组合索引、首页推荐缓存、看板按天预聚合与流式 Excel 导出满足指标。

## （二）安全

| 风险 | 防护措施 |
| --- | --- |
| 密码存储 | 全站采用 BCrypt 不可逆哈希，响应体与日志不输出密码字段 |
| SQL 注入 | MyBatis 一律使用 `#{}` 占位，动态排序字段采用白名单映射 |
| 越权访问 | 拦截器校验登录与角色，Service 层校验资源归属（本人/双方/本社团） |
| XSS 与 CSRF | JSP 输出统一 HTML 转义，写操作校验会话与同源来源 |
| 文件上传 | 白名单校验扩展名与 MIME、限制张数与大小、UUID 重命名存外部目录并禁执行 |
| 核销与脱敏 | 核销码绑定单据且一次性有效；演示数据脱敏，日志隐藏学号等敏感片段 |

## （三）可用性与降级

所有非核心依赖均做异常捕获与降级：Redis 异常时推荐切至数据库热门查询，活动名额切至数据库行锁扣减；PDF 凭证渲染失败时不回滚捐赠审核，页面提供重试入口；消息通知与操作日志写入异常仅记本地日志，不阻断主事务；超时定时任务按状态条件更新保证幂等。

## （四）兼容性

支持 Chrome 与 Edge 最新两个正式版本；桌面端按 1440×900（内容区宽 1240px）还原并适配 1366×768 分辨率，移动端保障基础浏览与提交。数据库严格限定 MySQL 5.7.17 语法，开发与构建脚本兼容 Windows 10/11 与 macOS。

## （三）对数据的影响与回退方式

1、无存量数据迁移：原闲置信息分散在 QQ 群与纸质台账中，不涉及存量库迁移（已确认无存量表变更）。

2、初始化数据：脚本仅写入三类预置模拟账号（密码均为 BCrypt 密文）、6 个一级分类、2 个社团账号、4 个校内自提点与 5 条积分规则，支持 `INSERT ... ON DUPLICATE KEY UPDATE` 幂等重跑。

3、保留与回退：业务数据逻辑保留，日志留存 1 年，统计日表留存 180 天；测试数据污染后重跑初始化快照即可恢复基线。
